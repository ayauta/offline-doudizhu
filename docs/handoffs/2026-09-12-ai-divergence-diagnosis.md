# 交接：分歧诊断（Spec 054）

日期：2026-09-12。接续 `2026-09-12-ai-strength-followup.md`。

本轮只做诊断：把问题从「哪一档更强」换成「在算法真正产生分歧的局面里，
哪个动作更常赢」。**`src/` 一行未改**，没有声称棋力提高，也没有把归档候选
重新应用到产品树。

## 1. 一句话结论

**归档候选够不到你点名的两个类别，而且是机制性的，不是采样不够。**

## 2. 机制（这是本轮最有用的发现）

`rankScoredPlayActions` 给每个候选动作 `floor(220 / 合法动作数)` 个分析器节点
（`src/core/ai/scoring-policy.ts:201-227`）。于是：

- **残局**：合法动作 2–3 个 → 每候选 70–110 个节点 → 有界搜索**把这只手解精确**；
  精确答案与搜索从哪个初值出发无关 ⇒ 两臂必然得到同一答案 ⇒ 出招相同。
- **开局**：20 张手牌约 30 个合法动作 → 每候选约 7 个节点 → 搜索几乎不下降，
  返回值基本**就是初值本身** ⇒ 补丁改的就是这里，所以分歧率 25%。

同一套算术解释了 200 副的全部结果：手牌 ≤7 张的 5,884 个决策里只有 5 处分歧，
而 20 张手牌的分歧率是 24.8%。

**推论：在现有节点预算下，修正估计对残局强度毫无作用。** 残局要走别的杠杆
（更多节点 / 更深 rollout / 更好的局面评估），不是更准的手牌划分。

## 3. 测量结果（200 副，种子 301–500）

12,694 个决策、492 处分歧（3.88%）、0.40 s/副。**492 处全部重放验证通过。**

| 类别 | 决策 | 分歧 | 配对差（候选−出厂） |
|---|---|---|---|
| 残局 ≤7 张 | 5,884 | 5 | **0.0 pp**（5 副） |
| 农民队友快出完 | 480 | 13 | **0.0 pp**（10 副） |
| 拆控制牌 | 463 | 127 | +5.7 pp（82 副）[−5.0, +16.5] |
| 开局 20 张 | 406 | 72 | +3.8 pp（65 副）[−4.6, +12.3] |
| 中局其他 | 5,461 | 275 | +4.3 pp（123 副）[−2.2, +10.9] |
| **合计** | 12,694 | 492 | **+5.1 pp**（166 副）[−0.2, +10.3] |

分支胜率（同一出厂续走）：候选动作 44.1%（651/1476），出厂动作 39.8%（588/1476）。

**诚实边界**：这是配对/交叉的**条件**量，采自出厂轨迹（on-policy），
**不是**上线胜率增益；分歧率 × 局部效应 ≠ 总体效应。类别之间有共同成因，
区间未做多重性校正。

## 4. 估计质量（Spec 053 没法给出的那条证据）

手牌 ≤12 张的 8,026 个决策，用独立的穷举 oracle（只用引擎的动作生成，
绝不用生产估计做剪枝）对照：

- **出厂估计有 1,147 次低于真值（14.3%）**——「乐观下界」成立；
- **候选估计只有 95 次不等于真值（1.2%）**，且方向都是**偏高**（保守）。

所以：出厂估计确实乐观，可行划分上界确实更接近真相，差约十二倍。
但 §2 说明，这**不足以**转化成残局强度。

## 6. 踩过的坑（省你时间）

1. **`playGame` 不接受外部策略对象**（`benchmarks/ai-tournament.ts:412-422` 用
   `profiles` 自建）。想注入策略必须自己写对局循环——诊断侧写了
   `playWithStrategies`，其余照抄。
2. **`generateShadowTree` 每次调用都会重写生成树**，所以往生成树里注入回归是无效的，
   必须注入到生成器本身。
3. 影子树的说明符要**全部**在镜像内部解析。指向镜像外的路径（哪怕文件真实存在）
   会因 Vite/Node 解析差异失败。镜像放在 `<gen>/src/**`，与真实树同构。
4. **一次性替换两次**：`replaceExactlyOnce` 早期只替换第一处，生成出「半候选」
   （一处初值、一处旧初值），两臂几乎相同——整轮诊断会因此作废。守卫抓到了它。
5. `import type { X }` 在 `verbatimModuleSyntax` 下被擦除，**不算**运行时导入边。
   仓库的 `scripts/runtime-import-graph.mjs` 是正确的事实源，不要用文本 grep 数导入。
6. 探针里若一个分析器实例问 220 个节点，会与生产的「每候选新建」语义不符；
   复刻生产预算时要用 `floor(220/动作数)` 每候选新建。

## 7. 建议的下一步（未执行）

按诊断出的最大效应选一个变量：**只调高出牌路径的每候选分析器额度**
（`decideEnhancedAi` 专家路的 `220` 与大师的 `rootAnalyzerNodes`），
用相同完成副牌、按副配对差值测 `default → expert`。

这是前两个被否决的实验（权重、深度）**没有**动过的那个杠杆，且大师在 120 ms
预算下仍有 3.8× 对 480 ms 窗口的余量，所以在 worker 预算内可测。

判据先定死：discovery 种子 301–700 的配对区间下界 > 0，**且**在保留的
validation 种子 10001–10400 上成立，才谈采纳；否则记录负结果并回滚。
若真正的约束是评估项质量而非搜索深度，被否决是预期结果。
