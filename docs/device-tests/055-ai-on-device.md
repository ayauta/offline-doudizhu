# Spec 055 AI 决策耗时：真机测量

Status: 可重复流程 + 2026-09-13 基线
Date: 2026-09-13

本文记录**怎么在真机上量 AI 决策耗时**，以及一次已完成的基线。产品约束见
[Spec 055](../specs/055-stronger-local-ai/spec.md)，失败与成功实验见
[实验记录](../research/ai-experiment-results.md)。

不记录设备标识、账号、通知或任何个人数据。下文的设备状态全部是复现所需的
技术状态。

## 一条命令

```bash
source scripts/activate-toolchain.sh
node scripts/phone-probe.mjs --deals 3
```

前置条件：设备已通过 USB 连接并授权；`.debug` 包已安装且**正在运行**。
脚本会自己找到 app 的 WebView 调试 socket、建立 `adb forward`、用 esbuild
打包探针、在设备上执行并打印结果。整轮约 10 秒。

可选参数：`--deals N`（默认 3）、`--package <id>`、`--serial <adb serial>`。

## 怎么读输出

探针让每个档位各打满几局，逐决策计时，分两种运行时：

| 模式 | 含义 |
| --- | --- |
| `unbounded` | 运行时永不到期，测的是**设计工作量的全部成本** |
| `shipped` | 用真实的每档预算，测的是**产品实际会跑的那条路**——报价用这个 |

`first` 是这一轮的第一个决策，与分位数分开报：冷引擎上只有它没被前面的样本
预热，而一局棋的第一个决策恰好就是冷的。

耗时依赖设备状态，**只比较同一状态下的两次运行**：

| 设备状态 | master `shipped` p50 |
| --- | --- |
| 锁屏（`mWakefulness=Dozing`，app 在 keyguard 后） | 约 124 ms |
| **解锁、app 在前台** | **约 44–50 ms** |

同一份代码相差约 2.5 倍。锁屏数字不代表玩家体验。

## 2026-09-13 基线

设备：小米 10S（`M2102J2SC`），Android 13，app 在前台，`maxWorlds=8`。
源码与产物见同日提交；同一份探针产物也在开发机上跑过。

| 档 | 模式 | first | p50 | p95 | max |
| --- | --- | ---: | ---: | ---: | ---: |
| master | `shipped` | 108–133 ms | **44–50 ms** | 128–136 ms | 141–153 ms |
| master | `unbounded` | 215–287 ms | 44–52 ms | 181–201 ms | 216–292 ms |
| casual | `shipped` | 0.8 ms | 0.0 ms | 0.6 ms | 1.0 ms |

开发机同一份产物：master `shipped` p50 约 11 ms。**这台手机约为开发机的 4.7 倍。**

连续 5 轮各 3 局，JS 堆稳定在 9.54 MB 不增长，master p50 无漂移——AI 与规则
路径跨局不泄漏。

## 这个流程覆盖不到什么

探针只测**决策本身**。Spec 055 的等待定义还包含冷启动、资源准备、消息传递与
呈现；其中消息传递和呈现**没有被测量**，连续对局的内存与发热也只有本页
上表的堆证据加上操作者的主观观察（2026-09-13：不卡、温度与充电常态无异）。

“明显更强”的结论按 spec 要求来自实际试玩，不来自本页任何数字。
